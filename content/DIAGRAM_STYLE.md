# Diagram style guide

Every paper gets one static SVG in `diagrams/CSxxx.svg`. They show the mechanism or the idea in one glance, not decoration. The 14 M2 diagrams follow this guide, and later ones must match them.

## Rules

- **Size:** `viewBox="0 0 400 210"`, no fixed pixel dependence. The panel shows it about 380 px wide, so text is rendered near 1:1.
- **Text:** system sans-serif, 10-13 px; monospace only for code, symbols and tape cells. Nothing under 10 px. Short labels; no sentences longer than about 55 characters.
- **Colour:** neutral ink `#1f2937`, line `#4b5563`, muted `#6b7280`. One accent per diagram, the paper's lane colour (see `data/lanes.json`), used for the key idea. Red `#b91c1c` and green `#047857` only for "bad outcome" and "good outcome".
- **Strokes:** 1.5 px lines; 2 to 3.4 px only to emphasise the one path that matters.
- **Shapes:** rounded rectangles (radius 6) for things, circles for nodes, arrows for flow. Arrow heads use the shared `a` marker.
- **Layout:** read left-to-right and top-to-bottom; leave margin; never let labels cross lines or each other.
- **Accessibility:** each file has `<title>` and `<desc>`, and the entry in `explanations.json` has `diagram_alt` (the text screen readers get, since the SVG is loaded through `<img>`). Do not rely on colour alone.
- **Safety:** no `<script>`, no event handlers, no external references. The validator (`tests/validate.html`, rule R7) rejects these.
- **Fidelity:** if it shows a worked example, it must be correct (the Dijkstra diagram's distances are checked by hand).

## Process

The M2 diagrams were generated by a small throwaway script so strokes, palette and fonts stay consistent; only the SVG files are kept. Edit an SVG directly if you only need a small change.

Check a new diagram by viewing it at 400 px wide and by running `tests/validate.html`.
